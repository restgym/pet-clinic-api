# Spring PetClinic REST for RESTgym

This repository is the RESTgym integration of Spring PetClinic REST. It is meant to be used as a Git submodule of [RESTgym](https://github.com/restgym/restgym) (in `apis/pet-clinic/`), which builds its Docker image and runs it with the testing tools: it does not work on its own.

More details (e.g., how 5XX responses are grouped into unique failures) are in the manifest, `restgym-api-manifest.yaml`.

## How RESTgym runs it

The image starts from the base image of RESTgym for Java 17 (`restgym/api-base:java17`), which contains the proxy and the collection of code coverage. `entrypoint.sh` starts the API on port 8080 with the profiles `h2` and `spring-data-jpa` (embedded H2 database, with the data in the jar). Nothing else runs in the container. The tools reach the API through the proxy of RESTgym, on port 9090.

## Changes made by RESTgym

### API

None.

### Specification

The original specification is `openapi-original.yaml` (OpenAPI 3.0.1): `src/main/resources/openapi.yml` at commit `8409c0a` (2025-08-16, version 3.4.3) of the original repository, unchanged. It has the same content as the `openapi.yml` in `spring-petclinic-rest.jar` (which has Windows line endings). At runtime, the API also serves a specification generated by springdoc (OpenAPI 3.1, at `/petclinic/v3/api-docs`), which is not the original.

- `pet-clinic.yaml`, given to the tools, has the same content as the original (server `http://localhost:9966/petclinic/api`, paths without the base path).
- `pet-clinic-openapi.json`, given to the tools, differs from it in the server: the base path `/petclinic/api` is in each path (e.g., `/petclinic/api/owners`), and the server URL is `http://localhost:8080` (since 2025-12-29). So the two specifications given to the tools differ: their operations are the same, but their paths and server URLs are not.

## Endpoints that may interfere with authentication

RESTgym handles the authentication of the requests, and the tools are not aware of it: an endpoint that ends or changes the session of RESTgym (e.g., logout, login as another user, change or deletion of the user of the proxy, of its password or of its roles) may make the tools fail for the rest of the run. Such endpoints may be removed from the specifications given to the tools.

None: RESTgym does not authenticate the requests to this API (it needs no authentication), so no endpoint can end or change a session of RESTgym. `POST /petclinic/api/users` creates users of the security of PetClinic, which is disabled in its default configuration.

## Known behavior of the API (kept as in the original)

- `GET /petclinic/api/oops` is in the specification but has no handler, so it returns 500. Unknown paths and invalid path parameters (e.g., `/owners/abc`) also return 500, since the API maps all exceptions to 500.
